把「翻平台、筛博主」交给 Bot：约定来源、格式与时间表，早上直接看摘要。本页把同一做法写成可复现步骤；博主列表请换成你自己的。官方机制侧，Skills 记「怎么做」，Routines 记「何时做」；新建或改完例程必须先 **Test run**——它会真的开网页、调已连接的工具。

实践里常见两层：一层是一天三次的时间线精选（带标签与「今日 3 条」）；一层是小时级的官方号雷达（没新动态就安静）。两层都要**窄规则**，避免空转烧用量。

## 适用

- 你每天要扫多个信息源，但只想看精华。
- 愿意先手动跑通一轮，再定例程。
- 接受「未核实」标签，不把个人说法当官方公告。
- 情报默认停在对话里；转发、发帖、群发另走审批。

## 什么时候不该用

- 你希望它**自动发帖或群发**「今日热点」——先按 [审批守门](/scenarios/approval-gate/) 把外发拦住；本场景默认只回对话。
- 来源全是必须登录才能看的私信 / 书签，而你又不肯装并维护 X 插件——公开网页可读，时间线首页通常要登录态。
- 例程间隔密到接近官方下限、或事件规则写成「每条新消息」——会空转与刷屏，见[新手坑点](/faq/pitfalls/)。
- 你把「未核实」当成可忽略的装饰——个人说法一旦被你二次转发，责任仍在你。

## 准备

- Bot：可用 [晨号](/bots/chenhao/) 或自建「情报」职责 Bot。描述里写清来源清单、输出格式、「不外发」「未核实要标」。
- 连接器：读首页时间线需安装并登录 **X** 插件；只查公开内容可不连。官方说明：读 X 上公开内容不一定要连账号；读私信、书签、首页时间线才需要。
- 权限：外发（发帖/群发）一律审批；本场景默认只回对话。本地执行通常不需要。
- 时区：例程时间表按你真实所在时区核对（示例为 Asia/Shanghai）。

## 步骤

1. 在对话里用五要素说清：结果=当日情报摘要；来源=你的列表；约束=不外发；交付=带链接的中文要点；停止点=若要转发必须审批。

2. 先**手动跑一次**，检查条数、去重、未核实标记。打开每条原文链接对一下，确认不是首页或过期帖。

![情报摘要结果卡示意](/tutorial/scenario-briefing-result.png)


3. 跑稳后存成 [技能](/workbench/skills/)，再建成 [例程](/workbench/routines/)。例程确认六项：归属 Bot、时间表与时区、输入来源、预期结果、审批边界、数据源缺失时怎么办。

4. **Test run** 通过才启用。测试会做真事——用你能接受的时间窗口试。

::: example 每日情报（替换占位）
```text
帮我做一个每天的 AI 动态情报：
1. 来源：X 上我的时间线和我关注的这几个博主：[博主列表]，公众号：[列表]，B站：[UP主列表]
2. 时间范围：当天 0 点到现在
3. 按互动从高到低挑最值得看的十几条
4. 每条：一句话说是什么事、大概热度、原文链接
5. 未证实的标「未核实」
6. 用我能直接看懂的中文写
7. 以后每天早上 [时间] 自动跑一次，跑完发给我（不要外发到别处）
```
:::

::: example 窄匹配精选（可选第二例程）
```text
每天 9:07、14:07、21:07 各跑一次，整理我 X 首页与 AI 有关的内容。
每条标：新发布 / 新玩法 / 旧闻翻炒；附链接；最后列出今天最值得看的 3 条并说明理由。
与上一次去重。不要发帖。
```
:::

## 进阶：官方号雷达（可选）

也可以加「只盯官方账号有无新发布」的小时级任务：没有新动态就保持安静。规则必须窄，避免空转烧用量。见[新手坑点](/faq/pitfalls/)。

::: example 官方号安静雷达
```text
每小时检查一次这些官方账号是否有新帖：[账号列表]。
有新内容才提醒我：一句话要点 + 链接；没有新动态不要发消息。
不要转发、不要评论。
```
:::

建议把「精选」与「雷达」拆成两个例程、两套技能：一个求全与排序，一个求快与安静。不要把「扫 900 条时间线」和「每小时雷达」糊在同一条宽规则里。

## 失败时怎么办

- **时间线读不到**：检查 X 插件是否仍登录；**Connect apps → Your plugins** 里看 Installed，必要时详情页重授权。
- **全是旧闻**：收紧时间范围并强制去重；在技能里写明「与上一次摘要去重」。
- **例程被暂停**：长时间离开后到 **Routines** 查看是否需恢复；也查用量是否耗尽。
- **Test run 像空转**：看运行历史是否真的请求了时间线；描述过宽或源不可达时，它可能只回一句套话——让它贴「实际读到的条数」。
- **未核实项消失了**：把「个人说法必须标未核实」写进描述与技能，不当成一次性口头提醒。
- **误触发发帖**：立刻禁用例程；检查是否把「发给我」理解成外发渠道；Auto Review 补上发帖 **Ask first**。

## 你要检查什么

- 是否误把宽规则（每条新消息）写成事件触发。
- Test run 是否真的读到了当前时间线，而不是空转。
- 「未核实」是否出现在个人说法上。
- 每条是否带可点开的原文链接，且不是首页。
- 与上一轮是否去重；「今日 3 条」是否有一句理由。
- 例程时间表的时区是否正确；归属 Bot 是否还在。
- 那一轮有没有出现发帖、转发、群发。

## 审批边界

::: approval
情报默认停在对话里。转发、发帖、群发必须另开审批；例程不要带「自动发布」。

例程产生的审批你不在场时大约十分钟会过期，过期卡片不会补跑动作。需要继续时让 Bot 再试一次。**Always allow** 不要送给「发帖」整类动作。
:::
