按顺序勾。做完前五步就有可展示的结果；后面几步是为了后天少踩坑。超时就把「装连接器 / Test run」留到加分项，不要为了赶时间乱点 **Reset**。

## 清单

### 1. 安装并登录（约 8 分钟）

- 打开：[安装与登录](/start/install/)
- 做什么：装好桌面端，完成 **Sign in**，能回到应用。
- 完成标准：侧边栏可见，能打开一个对话。

### 2. 确认资格（约 2 分钟）

- 打开：[订阅与资格](/start/plans/)
- 做什么：对照官方页确认账号含 Grok Bot；不在本站查价格数字。
- 完成标准：能正常发消息，无权限报错。

### 3. 扫一眼「设置 · 电脑」（约 3 分钟）

- 打开：[设置 · 电脑](/workbench/settings/computer/)（`Cmd/Ctrl+,` → 电脑）
- 做什么：看清「在这台电脑上执行」「转发流量」「更新 / 重置 Bot 的电脑」在哪；**先不要乱点重置**。
- 完成标准：能指认这几块控件的位置，并说出 Update 与 Reset 的差别（Update 优先）。

### 4. 建一位窄职责 Bot（约 7 分钟）

- 打开：[创建第一个窄职责 Bot](/start/first-bot/)
- 做什么：新建、写描述（含外发禁令）、不要叫「全能助手」。也可先从[Bot 馆](/bots/)导入模板再改描述。
- 完成标准：有名字、有职责、有至少一条审批边界。

![新建 Bot 流程示意](/tutorial/flow-create-bot.jpg)

### 5. 五要素下第一单（约 8 分钟）

- 打开：同上 + 可选场景[选题库](/scenarios/topic-inbox/)
- 做什么：结果 / 来源 / 约束 / 交付物 / 停止点写全；优先零外发任务。
- 完成标准：交付物落在约定位置，且停在你要求的节点。

::: example 零外发首单
```text
总结我贴的 3 个公开链接，输出到本对话：每条标题、一句话要点、原链接。
不要发邮件、不要发帖、不要改任何外部文档。
```
:::

### 6. 看云电脑一眼（约 2 分钟）

- 打开：[云电脑与接管](/start/computer/)
- 做什么：从对话打开电脑预览，知道任务在云端跑；需要密码 / 2FA / CAPTCHA 时用接管。
- 完成标准：能说出「合上笔记本任务仍可继续」。

### 7. 认一次审批卡（约 2 分钟，强烈建议）

- 打开：[安全与审批](/workbench/security/)
- 做什么：读懂 **Allow once** / **Always allow** / **Deny**；确认外发类动作不会被宽泛 Always allow 盖住。
- 完成标准：能说出「草稿卡 / 审批卡出现后，发送仍需人点」。

### 8. （可选）装一个只读连接器（约 5 分钟）

- 打开：[Connectors](/workbench/connectors/)
- 做什么：从 **Connect apps** 装一个你真用得到的插件，跑一只读任务；对话里用 `@` 挂接。
- 完成标准：有一次成功的挂接记录；没有误开写入。

### 9. （可选）草稿卡练习，不真发（约 5 分钟）

- 打开：[Channels](/workbench/channels/)
- 做什么：让 Bot 出一封给自己备用邮箱的测试草稿，在卡上点 **Discard**（或看清后再 **Send**）。
- 完成标准：理解「草稿 ≠ 已发送」。

## 可选加分（超出 30 分钟）

- 读[安全与审批](/workbench/security/)里的 Auto Review 三选择
- 浏览[场景库](/scenarios/)收藏一条
- 扫一眼[手机端](/start/mobile/)通知与草稿入口
- **不要**在第一天定高频例程；若好奇例程，只读[Routines](/workbench/routines/)概念，把 **Test run** 留给[7 天](/paths/7days/)

## 刻意先不做

- 不要一上来定高频例程。
- 不要把本机执行设成宽泛 **Always allow**。
- 不要 **Reset** 云电脑「试试看」。
- 不要同时建很多「全能」Bot。
- 不要在群聊里等邮件草稿卡——草稿与审批在一对一对话里。

## 为什么按这个顺序

先保证「能打开、能说话」，再保证「职责写窄」，再碰连接器与渠道，最后才例程。反过来做时，最常见的结果是：环境半残、Bot 名字叫新助手、第一单没有停止点，然后就开始定每小时例程——用量与误操作都会上去。

官方把「好请求」拆成结果、来源、约束、交付物、复查点五要素，就是为了让第一单可验收。本站[first-bot](/start/first-bot/)页有更长的写法示例。

## 做完后自测三问

1. 合上笔记本，你是否仍相信任务可以在云端继续？（见[云电脑](/start/computer/)）
2. 若 Bot 要发邮件，它是否必须先停？（见[安全](/workbench/security/)·[Channels](/workbench/channels/)）
3. 你是否知道 Reset 云电脑可能丢最近文件？（见[设置 · 电脑](/workbench/settings/computer/)）

三问都能答，30 分钟目标就算达成。


## 时间不够时的最小路径

若你只有 15 分钟：只做步骤 1、4、5（登录 → 窄职责 Bot → 零外发首单）。把设置电脑页、审批卡、连接器留到明天，但**仍然不要**当天定例程或 Reset。

若首单失败：先看对话里的报错原文，再对照[Q&A 手册](/faq/troubleshoot/)；不要连续换三个 Bot 名字重试。把失败的五要素原文留下来，改约束或停止点后再发一次。

## 五要素速查（贴到第一单上）

1. **结果**：你要看到什么（表格、摘要、文件路径）。
2. **来源**：链接、附件、连接器、只读范围。
3. **约束**：不能发邮件、不能改外部文档、不能合并。
4. **交付物**：格式与落点（对话内 / 云电脑路径）。
5. **停止点**：哪一步必须问你（外发、付款、接管登录）。

写不全就先补约束与停止点——这两项漏了最容易出事。

## 和手机的关系

桌面走完上述清单后，用[手机端](/start/mobile/)看同一对话是否同步、通知是否能提醒审批。手机上也能处理 **New Email** / **New Slack Message** 草稿卡，但新建复杂例程、改 Autoreview 细则仍以桌面为准（见官方 mobile 页说明）。
