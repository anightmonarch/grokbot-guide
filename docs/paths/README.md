不必按目录把整站读完。先拿最短闭环做出一个可验收的结果，再按角色或 7 天日程加深。本站是中文实践手册，事实以 docs.x.ai 为准；每页顶部有核对日期与来源块。

## 1. 三条路线

| 路线 | 适合谁 | 你将带走什么 |
| --- | --- | --- |
| [30 分钟入门](/paths/30min/) | 刚装好、怕走弯路 | 装好 → 窄职责 Bot → 五要素首单 → 看懂审批与云电脑 |
| [7 天进阶](/paths/7days/) | 想把流程变成技能与例程 | 每天一个可交付物；**Test run** 后才自动化 |
| [按角色](/paths/by-role/) | 创作者 / 开发者 / 运营 | 必读页 + 推荐场景，按需跳转 |

三条都服务同一原则：**先手动闭环，再技能，最后例程**。反过来做时，最常见的结果是环境半残、Bot 名叫「新助手」、第一单没有停止点，却已经定了每小时例程。

## 2. 建议顺序

1. 走完 [30 分钟](/paths/30min/)，确认客户端、账号与第一单。
2. 打开[设置 · 电脑](/workbench/settings/computer/)扫一眼本机执行与云电脑更新 / 重置，**先不要乱点 Reset**。
3. 到[场景库](/scenarios/)挑一条与你工作相近的跟做（优先零外发或只出草稿）。
4. 需要重复跑时再读[Skills](/workbench/skills/)与[Routines](/workbench/routines/)。
5. 有余力再开[7 天](/paths/7days/)或[按角色](/paths/by-role/)。
6. 外发、渠道、Cloud Agents 等能力，在首单稳定后再碰：[Channels](/workbench/channels/)、[Cloud Agents](/workbench/cloud-agents/)、[安全与审批](/workbench/security/)。

## 3. 和 Bot 馆、场景库的关系

[Bot 馆](/bots/)里的模板是「职责已经写窄」的起点；导入后仍要用你的五要素改第一单。教程页讲机制，模板页给人格与默认边界，场景页给可跟做步骤。

- 不知道「该干什么」→ [场景库](/scenarios/)
- 不知道「机制怎么运作」→ [入门](/start/)与[工作台](/workbench/)
- 已经有方向、缺人格边界 → [Bot 馆](/bots/)

一人公司可以三条角色都看，但同一周只深挖一条，避免同时开很多例程。

## 4. 读不懂或卡住时

- 机制问题：回[入门](/start/)对应章，或[Q&A 手册](/faq/troubleshoot/)。
- 「我该怎么用在工作上」：回[场景库](/scenarios/)。
- 设置项找不到：回[设置总览](/workbench/settings/)，电脑页优先。
- 常见弯路：回[新手坑点](/faq/pitfalls/)。

## 5. 三条路线怎么选（快速自测）

- 今天第一次打开应用 → 只走 [30 分钟](/paths/30min/)，不要跳 Day 4 定例程。
- 已经能稳定出交付物，想自动化 → [7 天](/paths/7days/)。
- 知道自己偏创作 / 工程 / 运营 → [按角色](/paths/by-role/)拿必读清单，仍建议先有一次五要素首单。
